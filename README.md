# База брендов

Сайт для редакции шопинга: поиск по базе брендов, добавление и редактирование.
База разделена на три категории — **мода, лайфстайл и красота**, — у каждой свой
набор полей.

```
GitHub Pages (React SPA)  ──HTTPS──▶  Supabase (Postgres + Auth)
```

Платного хостинга нет и не нужно: статика лежит на GitHub Pages, роль бэкенда
играет бесплатный проект Supabase. Правка, сделанная на сайте, видна всем
остальным сразу — пересобирать ничего не надо.

---

## Что уже умеет

- **Верхнеуровневый поиск по всем трём категориям сразу** плюс переключатель
  «Все / Мода / Лайфстайл / Красота» — первый фильтр над строкой поиска.
- Поиск мгновенный, на стороне браузера, с опечатками и в любой раскладке:
  запрос «Гуччи» находит `Gucci`, `Krasniy` находит «Красный Октябрь».
- Фильтры-чипы, которые строятся сами по колонкам-справочникам. Внутри
  категории — по всем её полям, в режиме «Все» — по общим для всех трёх.
- Добавление и редактирование через форму, собранную по структуре таблицы.
- Защита от параллельной правки: если бренд изменили, пока была открыта форма,
  сайт не затрёт чужие изменения молча.
- Предупреждение о дубле при добавлении бренда с уже существующим названием.
- Мягкое удаление («в архив») — записи из базы не исчезают.
- Поиск открыт всем, добавление и правки — по общему паролю редакции.

## Настройка с нуля

### 1. Supabase

Пошаговая инструкция — в [`supabase/README.md`](supabase/README.md): создать
проект, выполнить [`supabase/schema.sql`](supabase/schema.sql), завести учётку
редакции и скопировать два ключа. Там же — как перенести бренды из старой
Google-таблицы (`npm run migrate`).

### 2. GitHub

1. **Settings → Pages → Source: GitHub Actions**.
2. **Settings → Secrets and variables → Actions → вкладка Variables** — две
   переменные: `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.
3. Запустите workflow: **Actions → Deploy to GitHub Pages → Run workflow**
   (или просто сделайте любой пуш в `main`).

Сайт появится по адресу `https://<аккаунт>.github.io/<репозиторий>/`.

> Если репозиторий называется `<аккаунт>.github.io`, в
> `.github/workflows/deploy.yml` замените `VITE_BASE` на `/`.

Это именно *variables*, а не *secrets*: оба значения публичны по замыслу.
Anon-ключ лежит в собранном сайте и даёт только чтение — запись закрывают
политики RLS.

## Локальная разработка

```sh
npm install
cp .env.example .env      # и вписать два ключа Supabase
npm run dev               # http://localhost:5173
npm test                  # проверки поиска, фильтров, дублей и валидации
npm run build             # проверка сборки как на CI
```

Для отладки лучше завести отдельный проект Supabase, чтобы не править боевые
данные.

## Обслуживание

**Добавить поле.** Добавьте колонку `text` в нужную таблицу через
**Table Editor** в панели Supabase — на сайте она появится сама, и в форме, и в
карточке. Правка кода и пересборка не нужны.

**Настроить, как поле выглядит.** Таблица `field_defs`, одна строка на колонку:

| table_name | column_name | label | type | options | sort_order |
|---|---|---|---|---|---|
| `brands_fashion` | `fashion_kind` | Категория | `multiselect` | `{Одежда,Обувь,Сумки}` | 2 |
| `*` | `handmade` | Ручная работа | `bool` | `{да}` | 10 |

- `table_name` = `*` — правило сразу для всех трёх таблиц; строка с конкретной
  таблицей перебивает общую
- `type`: `text`, `longtext`, `url`, `select`, `multiselect`, `number`, `date`, `bool`
- `options` — подсказки для `select`/`multiselect`; вписать своё значение всё
  равно можно, и оно потом само появится в подсказках
- для `bool` в `options` указывается слово, которым галочка записывается
  (`да`); пустое `options` означает `TRUE`/`FALSE`
- `searchable = false` — убрать поле из поиска, `show_in_card = false` —
  спрятать из карточки
- любую ячейку можно оставить пустой — тогда работает значение по умолчанию

Подробности и оговорка про общий поиск — в [`supabase/README.md`](supabase/README.md).

**Сменить пароль редакции.** В панели Supabase: **Authentication → Users** →
строка `editor@brands.local` → **Reset password**. У всех, кто уже вошёл,
следующая попытка сохранить вернёт «Нужно войти под паролем редакции», и сайт
спросит новый.

**Обновить сайт.** Любой пуш в `main` пересобирает и выкладывает Pages.
Изменения *данных* пересборки не требуют.

## Что стоит знать

- **Три категории — три таблицы.** У них общее ядро полей (название, страна,
  город, сайт, теги, сегмент и т.д.) и свои специфичные поля. Поиск в режиме
  «Все» работает по общему ядру — то есть по полям, которые есть во всех трёх
  таблицах; внутри категории — по её полной схеме.
- **Пароль общий на всю редакцию.** Кто внёс правку, видно по полю `updated_by` —
  имя редактор указывает сам при входе. Полноценный аудит потребует отдельных
  учёток в Supabase Auth; менять придётся только `src/lib/auth.ts` — остальная
  архитектура остаётся прежней.
- **Поиск публичный.** Ссылку на сайт может открыть кто угодно; на запись это
  не влияет, но база видна всем, у кого есть адрес.
- **Если Supabase недоступен**, сайт продолжает работать на сохранённой копии
  базы в режиме чтения, а сохранение возвращает ошибку.
- **Скорость.** Первая загрузка тянет всю базу одним заходом, дальше поиск идёт
  локально и мгновенно. Повторные заходы показывают сохранённую копию сразу и
  обновляют её в фоне.
- **Бесплатный проект Supabase засыпает** после недели без запросов. Чтобы этого
  не случалось, `.github/workflows/keepalive.yml` раз в сутки дёргает базу одним
  запросом.

## Структура репозитория

```
supabase/schema.sql        таблицы, описания полей, вью и политики доступа
supabase/README.md         настройка проекта Supabase с нуля
scripts/migrate-from-sheets.mjs  разовый перенос базы из Google-таблицы
src/api/                   типы и клиент Supabase
src/lib/                   поиск, транслитерация, схема, категории, кэш, вход
src/components/            форма бренда, фильтры, список, модалка входа
src/pages/                 поиск, карточка, добавление, редактирование
src/store/                 загрузка базы и общая обвязка записи
tests/smoke.ts             проверки поиска, фильтров, дублей и валидации
.github/workflows/         сборка, деплой на Pages и пинг Supabase
```
