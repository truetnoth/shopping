# База брендов

Сайт для редакции шопинга: поиск по базе брендов, добавление и редактирование.
Источник правды остаётся Google-таблицей — всё, что меняется на сайте,
записывается прямо в неё.

```
GitHub Pages (React SPA)  ──HTTPS──▶  Apps Script Web App  ──▶  Google Sheets
```

Платного хостинга нет и не нужно: статика лежит на GitHub Pages, роль бэкенда
играет Google Apps Script, привязанный к самой таблице.

---

## Что уже умеет

- Поиск по всей базе — мгновенный, на стороне браузера, с опечатками и в любой
  раскладке: запрос «Гуччи» находит `Gucci`, `Krasniy` находит «Красный Октябрь».
- Фильтры-чипы, которые строятся сами по колонкам-справочникам.
- Добавление и редактирование через форму, собранную по структуре таблицы.
- Защита от параллельной правки: если строку изменили в таблице, пока была
  открыта форма, сайт не затрёт чужие изменения молча.
- Предупреждение о дубле при добавлении бренда с уже существующим названием.
- Мягкое удаление («в архив») — строки из таблицы не исчезают.
- Поиск открыт всем, добавление и правки — по общему паролю редакции.

## Настройка с нуля

### 1. Таблица

Рабочая таблица — [«Бренды»](https://docs.google.com/spreadsheets/d/1OW3j4We8Z6273lkvSLu5_Abtr8v6J3B8jTXJ8VnmOBY/edit):
32 бренда, 12 колонок (`Бренд`, `Страна`, `Категория`, `Ценовой сегмент`,
`Для кого`, `Ссылка`, `Теги`, `Характеристика`, `Есть свое производство`,
`Ручная работа`, `Город`, `Год основания`).

К ним нужно добавить служебные колонки `id`, `updated_at`, `updated_by`,
`archived` — это делает функция `setupSheet()` из следующего шага.

> Колонка `id` обязательна. Редакция сортирует и фильтрует лист, поэтому номер
> строки не годится в качестве идентификатора бренда.

Заготовка листа `_schema` под эти колонки уже лежит в
[`apps-script/schema-brands.tsv`](apps-script/schema-brands.tsv): откройте файл,
скопируйте всё содержимое и вставьте в ячейку `A1` листа `_schema` — Google
разложит по колонкам сам. Она задаёт, что `Категория`, `Теги` и `Для кого` —
мультизначные поля, `Ценовой сегмент`, `Город` и `Характеристика` —
справочники, `Ссылка` — ссылка, а `Есть свое производство` и `Ручная работа` —
галочки, которые записываются словом «да», как это уже сделано в таблице.

> Колонка `column` в `_schema` должна точно совпадать с заголовком в таблице.
> Если заголовок переименовали, поправьте и `_schema` — иначе строка перестанет
> действовать и колонка молча вернётся к типу «текст».

### 2. Apps Script

1. В таблице: **Расширения → Apps Script**.
2. Замените содержимое `Код.gs` на файл [`apps-script/Code.gs`](apps-script/Code.gs)
   из этого репозитория.
3. Запустите две функции. Функция выбирается в выпадающем списке на панели
   редактора, рядом с кнопкой **Run**; аргументы там передать нельзя, поэтому
   всё, что нужно вписать, вписывается прямо в файл.
   - `setupSheet` — создаст недостающие служебные колонки, лист `_schema`
     и проставит `id` существующим строкам;
   - `setEditorPassword` — впишите пароль в строку `var NEW_PASSWORD = '';`
     вверху файла, сохраните, запустите функцию, затем **сотрите пароль
     обратно и снова сохраните**. В свойствах скрипта остаётся только SHA-256:
     сам пароль нигде не хранится, передайте его редакции привычным способом.
4. **Deploy → New deployment → Web app**:
   - Execute as: **Me**
   - Who has access: **Anyone**
5. Скопируйте выданный URL (заканчивается на `/exec`).

Если данные лежат не на первом листе, задайте имя листа в
**Project Settings → Script Properties**, свойство `SHEET_NAME`.
Колонка с названием бренда по умолчанию — первая неслужебная; переопределяется
свойством `NAME_COLUMN`.

### 3. GitHub

1. Создайте репозиторий и залейте туда содержимое этой папки:
   ```sh
   git init && git add . && git commit -m "База брендов"
   git branch -M main
   git remote add origin git@github.com:<аккаунт>/<репозиторий>.git
   git push -u origin main
   ```
2. **Settings → Pages → Source: GitHub Actions**.
3. **Settings → Secrets and variables → Actions → Variables → New variable**:
   имя `VITE_API_URL`, значение — URL веб-приложения из шага 2.
4. Запустите workflow: **Actions → Deploy to GitHub Pages → Run workflow**
   (или просто сделайте любой пуш в `main`).

Сайт появится по адресу `https://<аккаунт>.github.io/<репозиторий>/`.

> Если репозиторий называется `<аккаунт>.github.io`, в
> `.github/workflows/deploy.yml` замените `VITE_BASE` на `/`.

## Локальная разработка

```sh
npm install
cp .env.example .env      # и вписать VITE_API_URL
npm run dev               # http://localhost:5173
npm test                  # проверки поиска, фильтров и валидации
npm run build             # проверка сборки как на CI
```

Для отладки лучше сделать копию таблицы и отдельный деплой скрипта, чтобы не
править боевые данные.

## Обслуживание

**Добавить колонку в базу.** Допишите её в шапку листа. На сайте она появится
сама — и в форме, и в карточке бренда. Правка кода не нужна.

**Настроить, как колонка выглядит на сайте.** Лист `_schema`, одна строка на
колонку:

| column | label | type | options | required | searchable | showInCard | order |
|---|---|---|---|---|---|---|---|
| `Категория` | Категория | `multiselect` | `Одежда, Верхняя одежда, Обувь, Сумки` | TRUE | TRUE | TRUE | 2 |
| `Ручная работа` | Ручная работа | `bool` | `да` | FALSE | FALSE | TRUE | 10 |

- `type`: `text`, `longtext`, `url`, `select`, `multiselect`, `number`, `date`, `bool`
- `options` — подсказки для `select`/`multiselect`; вписать своё значение всё
  равно можно, и оно потом само появится в подсказках
- для `bool` в `options` указывается слово, которым галочка записывается в
  таблицу (`да`); пустое `options` означает `TRUE`/`FALSE`
- `searchable: FALSE` — убрать поле из поиска, `showInCard: FALSE` — спрятать
  из карточки
- любую ячейку можно оставить пустой — тогда работает значение по умолчанию

**Сменить пароль редакции.** В редакторе Apps Script впишите новый пароль в
`NEW_PASSWORD`, запустите `setEditorPassword`, сотрите пароль обратно и
сохраните файл. У всех, кто уже вошёл, следующая попытка сохранить вернёт
«Неверный пароль», и сайт спросит новый.

**Обновить код бэкенда.** После правки `Code.gs` (вручную или `npm run push:script`
при настроенном `apps-script/.clasp.json`) опубликуйте новую версию:
**Deploy → Manage deployments → карандаш → Version: New version → Deploy**.

> ⚠️ Кнопка **New deployment** выдаёт **другой URL** и ломает уже собранный
> фронт. Для обновлений всегда «New version» внутри существующего деплоя.

**Обновить сайт.** Любой пуш в `main` пересобирает и выкладывает Pages.

## Что стоит знать

- **Пароль общий на всю редакцию.** Кто внёс правку, видно по полю `updated_by` —
  имя редактор указывает сам при входе. Полноценный аудит потребует перехода на
  вход через Google с белым списком почт; менять придётся только проверку в
  `doPost` — остальная архитектура остаётся прежней.
- **Поиск публичный.** Ссылку на сайт может открыть кто угодно; на запись это
  не влияет, но база видна всем, у кого есть адрес. Сама таблица сейчас тоже
  открыта на чтение по ссылке — если это не задумано, доступ стоит сузить
  (на работу сайта это не повлияет: скрипт ходит в таблицу от имени владельца).
- **Если Google недоступен**, сайт продолжает работать на сохранённой копии
  базы в режиме чтения, а сохранение возвращает ошибку.
- **Скорость.** Первая загрузка тянет всю базу одним запросом (0.5–2 сек),
  дальше поиск идёт локально и мгновенно. Повторные заходы показывают
  сохранённую копию сразу и обновляют её в фоне, только если в таблице
  действительно что-то поменялось.
- **Квоты Apps Script** (порядка 20 000 запусков в сутки) при таком профиле
  использования недостижимы.

## Структура репозитория

```
apps-script/Code.gs        бэкенд: чтение, запись, авторизация, блокировки
apps-script/schema-brands.tsv  заготовка листа _schema под текущие колонки
src/api/                   типы и HTTP-клиент
src/lib/                   поиск, транслитерация, схема, кэш, пароль
src/components/            форма бренда, фильтры, список, модалка входа
src/pages/                 поиск, карточка, добавление, редактирование
src/store/                 загрузка базы и общая обвязка записи
tests/smoke.ts             проверки поиска, фильтров и валидации
.github/workflows/         сборка и деплой на GitHub Pages
```
