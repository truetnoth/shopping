# Настройка Supabase

Разовая настройка бэкенда. Занимает минут десять, повторять не нужно.

## 1. Создать проект

1. [supabase.com](https://supabase.com) → **New project**.
2. Регион — ближайший к редакции (`Central EU (Frankfurt)`).
3. Пароль базы данных, который предложит форма, — это пароль **администратора
   Postgres**, а не пароль редакции. Сохраните его в менеджере паролей и больше
   про него не вспоминайте.

## 2. Создать таблицы

**SQL Editor** → **New query** → вставить целиком содержимое
[`schema.sql`](./schema.sql) → **Run**.

Скрипт создаёт три таблицы (`brands_fashion`, `brands_lifestyle`,
`brands_beauty`), таблицу описаний полей `field_defs`, вью `brand_fields` и
политики доступа. Запускать его повторно безопасно.

## 3. Завести учётку редакции

Вся редакция ходит под одной учёткой — редактор вводит только пароль.

1. **Authentication** → **Providers** → **Email**: выключить
   *Confirm email* (подтверждать почту некому — адрес технический).
2. **Authentication** → **Users** → **Add user** → **Create new user**:
   - Email: `editor@brands.local` — ровно так, этот адрес зашит в
     `src/lib/auth.ts`;
   - Password: пароль, который получит редакция;
   - **Auto Confirm User**: включить.

Сменить пароль редакции позже: **Authentication** → **Users** → на строке
пользователя → **Reset password**.

## 4. Прописать ключи

**Settings** → **API**, скопировать **Project URL** и ключ **anon public**.

Локально — в `.env`:

```
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
```

Для сборки сайта — в GitHub: **Settings** → **Secrets and variables** →
**Actions** → вкладка **Variables** → две переменные с теми же именами.

Это именно *variables*, а не *secrets*: оба значения и так попадают в собранный
сайт, спрятать их нельзя. Базу закрывает не ключ, а политики RLS: роли `anon` не
выдано ни одной, поэтому без входа REST API отдаёт пустой список. Секретным
является только ключ `service_role`, и он в проекте нигде не используется.

## Как менять поля потом

Состав полей определяют **сами колонки таблиц** — как раньше его определяла
шапка листа. Чтобы добавить поле:

1. **Table Editor** → нужная таблица → **+** → новая колонка типа `text`,
   `Default value` — пустая строка, снять `Is Nullable`.
2. Всё. Поле появится на сайте после перезагрузки страницы — как текстовое,
   с заголовком, равным имени колонки. Пересобирать сайт не нужно.

Чтобы задать русское название, тип и варианты — добавить строку в `field_defs`
(**Table Editor** → `field_defs` → **Insert row**):

| поле | что писать |
|---|---|
| `table_name` | имя таблицы, либо `*` — правило сразу для всех трёх |
| `column_name` | имя колонки |
| `label` | заголовок на сайте |
| `type` | `text`, `longtext`, `url`, `select`, `multiselect`, `number`, `date`, `bool` |
| `options` | варианты для select/multiselect; для `bool` — одно значение, которым пишется галочка (`да`) |
| `sort_order` | порядок в форме и карточке |

Колонка, которой в `field_defs` нет, всё равно работает — просто как обычное
текстовое поле.

**Важно про общий поиск:** в режиме «Все» сайт ищет и фильтрует по полям,
которые есть **во всех трёх** таблицах. Добавили колонку только в «Красоту» —
она видна внутри «Красоты», но не в общей выдаче. Нужна везде — добавьте её во
все три таблицы с одинаковым именем.

## Про сон бесплатного проекта

Бесплатный проект засыпает после недели без запросов. Чтобы сайт не встречал
редакцию ошибкой, в репозитории лежит `.github/workflows/keepalive.yml` — он
раз в сутки дёргает базу одним запросом. Отдельной настройки не требует, но
использует те же переменные `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.
